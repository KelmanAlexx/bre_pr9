# Политика доступа к репозиторию

Права участников удалённого Git-репозитория назначаются по принципу минимально необходимых привилегий.

| Роль | Разрешённые действия |
|---|---|
| Владелец / администратор | Управление участниками и настройками проекта, защита веток, назначение ролей, управление секретами CI/CD. |
| Сопровождающий (Maintainer) | Проверка и слияние запросов на изменение, управление рабочими ветками и релизами. |
| Разработчик (Developer) | Чтение репозитория, создание веток, отправка изменений в собственные ветки, создание Pull/Merge Request. |
| Наблюдатель (Read-only) | Просмотр и клонирование репозитория без отправки изменений. |

## Защита основной ветки `main`

- Запретить прямую отправку коммитов разработчиками в `main`.
- Выполнять слияние через Pull Request / Merge Request.
- Требовать как минимум одно одобрение ответственного участника.
- Запретить принудительную отправку (`force push`) и удаление `main`.
- По возможности запускать автоматические проверки перед слиянием.
- Хранить токены, пароли и строки подключения в Secret/CI Variables, а не в исходном коде.

Локальная команда `git init` создаёт историю версий, но не настраивает сетевые роли пользователей. Перечисленные ограничения применяются после размещения репозитория на GitHub, GitLab или другом Git-сервисе.
